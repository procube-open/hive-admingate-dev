# テスト項目書

## 1. テスト対象の概要
本書は、IDM の認証設定、ユーザー管理、チーム管理、ワークフロー管理、および接続確認に関する手動検証項目を整理したものである。  
現時点では自動化を前提にした記載ではなく、実際に手動で確認する際の観点を中心にまとめる。

## 2. 共通前提条件
- 対象環境で IDM と Admingate が起動していること
- `https://idm3.admingate-dev.procube-demo.jp/` にアクセスできること
- `https://admingate-core.admingate-dev.procube-demo.jp/` にアクセスできること
- `test-user` アカウントが存在し、パスワードと TOTP 認証が有効であること
- TOTP シークレットが有効であること
- 対象データの事前準備が完了していること
- `mock-ssh-server` が接続先として定義されていること

## 3. テストケース一覧

### TC-01: ログイン確認
- 対象: IDM ログイン画面
- 前提条件:
  - IDM ログイン画面にアクセスできる
  - `test-user` ユーザーが存在している
  - TOTP 認証が利用可能である
- 入力:
  - ID: `test-user`
  - パスワード: 設定済みの有効なパスワード
  - TOTP コード: 現在有効なコード
- 実行手順:
  1. ログイン画面にアクセスする
  2. ユーザー名を入力する
  3. パスワードを入力する
  4. TOTP コードを入力する
  5. ログインボタンを押下する
- 期待結果:
  - ログインが成功する
  - 初期画面またはログイン後の画面が表示される
  - 認証エラーが表示されない

### TC-02: ユーザー作成確認
- 対象: 認証設定 > ユーザ編集
- 前提条件:
  - 認証済み状態である
  - ユーザ編集画面にアクセスできる
- 入力:
  - UID: `test-user1`
  - sn: `テスト`
  - cn: `ユーザ`
  - ロール: `利用者`
  - email: `test@procube.jp`
  - 所属組織: `procube`
- 実行手順:
  1. 認証設定メニューから「ユーザ編集」を選択する
  2. 「追加」ボタンを押下する
  3. 必要項目を入力する
  4. 保存ボタンを押下する
  5. 発効する
  6. 一覧に作成したユーザーが表示されることを確認する
- 期待結果:
  - 新規ユーザーが一覧に追加される
  - 入力した内容が正しく表示される
  - 保存と発効が正常に完了する

### TC-03: ユーザー削除確認
- 対象: 認証設定 > ユーザ編集
- 前提条件:
  - 作成済みの `test-user1` が存在している
  - 該当ユーザーの編集画面を開ける
- 入力:
  - ユーザー: `test-user1`
- 実行手順:
  1. 対象ユーザーの「編集」ボタンを押下する
  2. 「削除」を選択する
  3. 削除確認を実施する
  4. 発効する
  5. 一覧から対象ユーザーが消えていることを確認する
- 期待結果:
  - 対象ユーザーが一覧から削除される
  - 削除後に重複や表示崩れがない

### TC-04: チーム作成確認
- 対象: 認証設定 > チーム編集
- 前提条件:
  - 認証済み状態である
  - チーム編集画面にアクセスできる
  - `test-user` が既存ユーザーとして登録済みである
- 入力:
  - ID: `testgroup1`
  - 名前: `テストチーム`
  - メンバー: `test-user`
- 実行手順:
  1. 認証設定メニューから「チーム編集」を開く
  2. 「追加」ボタンを押下する
  3. チーム名と ID を入力する
  4. メンバーとして `test-user` を選択する
  5. 保存して発効する
  6. 一覧に該当チームが表示されることを確認する
- 期待結果:
  - チームが正常に作成される
  - 指定したメンバーが割り当てられている
  - 一覧表示が正しい

### TC-05: チーム削除確認
- 対象: 認証設定 > チーム編集
- 前提条件:
  - 作成済みの `testgroup1` が存在している
- 入力:
  - チーム: `testgroup1`
- 実行手順:
  1. 対象チームの「編集」ボタンを押下する
  2. 「削除」を実行する
  3. 確認を行い、発効する
  4. 一覧から対象チームが消えていることを確認する
- 期待結果:
  - 対象チームが表示されなくなる
  - 関連する一覧や状態が整合している

### TC-06: 作業申請の新規作成確認
- 対象: ワークフロー設定 > 作業申請
- 前提条件:
  - 認証済み状態である
  - `test-user` がユーザーとして登録済みである
  - `mock-ssh-server` が接続先として定義済みである
- 入力:
  - 作業名: `検証作業1`
  - 作業期間: 追加
  - 接続先: `mock-ssh-server`
  - 作業者: `test-user`
  - 管理者: `test-user`
- 実行手順:
  1. 「ワークフロー設定」→「作業申請」を開く
  2. 「新規作成」を押下する
  3. 作業名と期間を入力する
  4. 接続先を選択する
  5. 作業者と管理者を選択する
  6. 保存する
  7. 作業が一覧に表示されることを確認する
- 期待結果:
  - 新規作業が作成される
  - 入力した項目が一覧に反映される
  - 保存処理が正常に完了する

### TC-07: 管理者への申請と承認確認
- 対象: ワークフロー設定 > 作業申請 > 要承認作業 / 承認済み作業
- 前提条件:
  - 新規作業が作成済みである
  - 対象作業の詳細画面に遷移できる
- 入力:
  - 対象作業: `検証作業1`
- 実行手順:
  1. 作業一覧から対象作業を選択する
  2. 作業詳細画面で「管理者に申請する」を押下する
  3. 「要承認作業」一覧で対象作業が表示されることを確認する
  4. 申請対象の詳細画面を開く
  5. 「承認」を押下する
  6. 発効する
  7. 「承認済み作業」一覧で対象作業が表示されることを確認する
- 期待結果:
  - 申請処理が成功する
  - 承認処理が成功する
  - 承認済み一覧に対象作業が表示される

### TC-08: 接続確認
- 対象: Admingate の作業一覧と対象作業画面
- 前提条件:
  - 対象作業が作成済みである
  - `mock-ssh-server` が接続先として設定済みである
  - Admingate の操作画面へアクセスできる
- 入力:
  - 作業 ID: 対象作業の ID
  - 接続先: `mock-ssh-server`
- 実行手順:
  1. Admingate のトップページへアクセスする
  2. 作業一覧画面が表示されることを確認する
  3. 対象作業を選択する
  4. 対象作業の詳細画面へ遷移する
  5. 接続ボタンを押下する
  6. 接続状態とエラー状態を確認する
- 期待結果:
  - 対象作業に遷移できる
  - 接続が実行される
  - 接続切断エラーが発生していない
  - 再接続や異常表示の原因が見当たらない

### TC-09: IDM ログアウト後の再アクセス確認
- 対象: IDM3 のログイン画面
- 前提条件:
  - IDM3 にログイン済みである
  - ログアウト操作が可能である
- 入力:
  - なし
- 実行手順:
  1. IDM3 上でログアウトを実行する
  2. ログイン画面に戻ることを確認する
  3. ブラウザを再読み込みまたは再アクセスする
  4. ログイン画面が表示されることを確認する
- 期待結果:
  - ログアウト後にセッションが破棄される
  - 再アクセス時にログイン画面へ遷移する
  - 前回の認証状態が残っていない

### TC-10: Admingate Core のログアウト後の再アクセス確認
- 対象: Admingate Core
- 前提条件:
  - Admingate Core にログイン済みである
  - ログアウト機能が利用可能である
- 入力:
  - なし
- 実行手順:
  1. Admingate Core からログアウトする
  2. ログイン画面に遷移することを確認する
  3. 再アクセスまたはブラウザ再読み込みを行う
  4. 再度ログイン画面が表示されることを確認する
- 期待結果:
  - ログアウト後にセッションが解除される
  - 認証済み画面にアクセスできない
  - 再アクセス時にログイン画面が表示される

### TC-11: Admin-gate での Windows への RDP 接続確認
- 対象: Admin-gate から Windows への接続
- 前提条件:
  - Admin-gate にアクセスできる
  - 接続対象の Windows 環境が利用可能である
  - RDP 接続権限がある
- 入力:
  - 接続先: Windows ホスト
  - 接続種別: RDP
- 実行手順:
  1. Admin-gate で対象の Windows 環境を選択する
  2. RDP 接続を起動する
  3. 接続後の画面が表示されることを確認する
  4. 画面の操作が可能であることを確認する
- 期待結果:
  - Windows のデスクトップに接続できる
  - 認証や画面表示に問題がない
  - 操作が通常通りに可能である

### TC-12: Admin-gate での Socket-Warp 利用接続確認
- 対象: Admin-gate からの socket-warp 接続
- 前提条件:
  - Admin-gate にアクセスできる
  - 対象環境が socket-warp に対応している
- 入力:
  - 接続先: 対象ホストまたはサービス
  - 接続種別: socket-warp
- 実行手順:
  1. Admin-gate の接続画面から socket-warp を選択する
  2. 対象接続先を指定して接続する
  3. 接続後の画面や応答を確認する
- 期待結果:
  - socket-warp 接続が成立する
  - 接続先に対して通常の操作が可能である
  - 接続エラーや異常が発生しない

### TC-13: Admin-gate でのブラウザアクセス確認

- 前提条件:
  - Admin-gate にアクセスできる

- 入力:
  - 接続先: ブラウザアクセス対象

  1. Admin-gate の対象一覧からブラウザアクセスを選択する
  2. 接続を起動する
  3. 対象画面が表示されることを確認する
  4. 画面操作を行って応答を確認する
- 期待結果:
  - ブラウザ画面が正常に表示される
  - 操作が可能である
  - 接続エラーや表示崩れがない

### TC-14: Windows への RDP 接続時のショートカットキー検証
- 対象: RDP で接続中の Windows
- 前提条件:
  - Windows へ RDP 接続済みである
  - 接続先の Windows で操作できる状態である
- 入力:
  - ショートカットキー一覧を順次実行する
- 実行手順:
  1. RDP 接続中の Windows を前提とする
  2. 各ショートカットキーを実行する
  3. その結果が期待どおりに動作するかを確認する
  4. できないものについては、制限や未対応の理由を記録する
- 期待結果:
  - 以下のショートカットキーは動作する
    - Ctrl + Alt + Delete
    - Ctrl + Shift + Esc
    - Win + L
    - Alt + Tab
    - Alt + F4
    - Win + D
    - Win + E
    - Win + Tab
    - Win + 矢印キー
    - Win + M
    - Ctrl + C / X / V
    - Ctrl + Z / Y
    - Ctrl + A
    - Ctrl + F
    - Ctrl + W
    - Win + Shift + S
    - 半角／全角キー
    - Win + R
    - Win + I
    - Win + X
    - Win + .
  - 実際に動作しない、または制限があるものについては、記録する

### TC-15: Windows への RDP 接続時の音声確認
- 対象: RDP 接続中の Windows
- 前提条件:
  - Windows へ RDP 接続済みである
  - 音を再生可能な対象アプリや音源が準備されている
- 入力:
  - 音声再生対象: 試験用の音または OS の音
- 実行手順:
  1. RDP 接続中の Windows で音声を再生する
  2. ローカル側で音が聞こえるか確認する
  3. 音が聞こえない場合は、設定や接続制限を確認する
- 期待結果:
  - 音声が正常に聞こえる場合は、RDP で音が伝達されていると判断できる
  - 音が聞こえない場合は、環境設定や制限を記録する

## 4. 期待される確認観点
- 画面遷移が要件どおりであること
- 入力値が正しく保存されること
- 一覧に登録内容が反映されること
- 削除処理後に対象データが消えること
- 承認フローが正しく進行すること
- 接続の問題が発生していないこと
- 不要なエラーダイアログや異常表示が出ていないこと
- ログアウト後にセッションが正しく切れて再認証が必要になること
- RDP 接続時のキー操作や音声が要件どおりに動作すること
- Admin-gate の接続種別ごとに、期待する操作が行えること
